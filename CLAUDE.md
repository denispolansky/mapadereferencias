# Cómo trabajar en este repo

Ver `ESPECIFICACION.md` para la memoria completa del proyecto (decisiones, modelo de contenido, alcance del MVP). Este archivo es sobre el flujo de trabajo con git, no sobre el producto.

## Flujo de git

- Mientras se está explorando ideas o iterando sobre diseño/arquitectura: trabajar directamente sobre `main`. No crear ramas por defecto.
- Commits pequeños y frecuentes, con mensajes claros y descriptivos. Preferir varios commits chicos a uno grande.
- No abrir Pull Requests automáticamente. Solo abrir uno cuando la autora lo pida explícitamente, o cuando se complete un hito importante (una funcionalidad terminada, un rediseño significativo, una sección nueva completamente implementada).

## Cuándo consultar antes de implementar

- Cambios importantes de estructura, arquitectura, diseño o experiencia de usuario: explicar brevemente la propuesta, por qué se recomienda, y qué alternativas existen. La autora decide de forma consciente.
- Cambios chicos, correcciones o mejoras evidentes: implementar directamente, sin consultar antes.
